# The U256 Type

Every value on the EVM stack is a 256-bit unsigned integer. We represent this as a newtype over `[u8; 32]` in **big-endian** byte order (most significant byte first).

## Why big-endian?

The EVM specification defines stack values and storage keys in big-endian. When you `PUSH32 0x00...01`, byte index 0 is the most significant and byte index 31 is the least significant. Our internal representation matches this convention, so no byte-swapping is needed when reading from bytecode.

## The newtype pattern

Rather than passing around raw `[u8; 32]` arrays, we wrap them in a struct:

```rust
#[derive(Clone, Copy, Debug, Default, Hash, PartialEq, Eq)]
pub struct U256([u8; 32]);
```

This gives us:
- **Type safety** — you can't accidentally pass a random byte array where a U256 is expected
- **Method namespace** — we can implement `U256::wrapping_add`, `U256::checked_div`, etc.
- **Operator overloading** — `impl Add for U256` lets us write `a + b` naturally

## Wrapping arithmetic

EVM arithmetic wraps on overflow. `MAX + 1 = 0`. This is not a bug — it's the specification. The EVM has no concept of overflow traps or panics at the arithmetic level. Wrapping is implemented by simply discarding the carry bit:

```rust
pub fn wrapping_add(self, rhs: Self) -> Self {
    let mut result = [0u8; 32];
    let mut carry: u16 = 0;
    for i in (0..32).rev() {
        let sum = self.0[i] as u16 + rhs.0[i] as u16 + carry;
        result[i] = sum as u8;
        carry = sum >> 8;
    }
    Self(result)
}
```

## Division by zero

In most languages, dividing by zero is undefined or panics. In the EVM, `x / 0 = 0`. This is explicit in the Yellow Paper. Our `checked_div` method returns `U256::ZERO` when the divisor is zero.
